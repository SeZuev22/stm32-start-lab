# 01 — Blink на Blue Pill

Первый практический пример проекта **STM32 Start Lab**.

В данном примере используется плата **Blue Pill** на микроконтроллере **STM32F103C8T6**.

Цель работы — пройти полный базовый путь разработки программы для STM32:

**STM32CubeMX → настройка микроконтроллера → генерация проекта → STM32CubeIDE → написание программы → сборка → прошивка через ST-LINK V2 → проверка работы на реальной плате.**

Проект проверен на реальном оборудовании.

---

## 1. Что получится в результате

После выполнения примера встроенный светодиод Blue Pill будет работать по следующему алгоритму:

1. включение на `300 мс`;
2. выключение на `300 мс`;
3. повторение мигания `5 раз`;
4. пауза `2 секунды`;
5. повтор всей последовательности.

Таким образом, студент получает первый полностью работающий проект STM32 и проходит путь от настройки микроконтроллера до загрузки программы в его Flash-память.

## 4. Используемый микроконтроллер

На плате Blue Pill установлен микроконтроллер:

```text
STM32F103C8T6
```

Основные характеристики, важные для первого знакомства:

- ядро Arm Cortex-M3;
- Flash-память;
- SRAM;
- цифровые входы и выходы GPIO;
- таймеры;
- интерфейсы USART, SPI, I2C;
- интерфейс SWD для программирования и отладки.

В данном примере используется только один цифровой выход GPIO — `PC13`.

## 6. Почему используется MCU Selector

Blue Pill является сторонней платой и не относится к официальным отладочным платам ST типа Nucleo или Discovery.

Поэтому проект создаётся не через `Board Selector`, а через выбор конкретного микроконтроллера:

```text
STM32F103C8T6
```

Это позволяет вручную настроить необходимые выводы и периферию.

## 9. Начальное состояние светодиода

Откройте:

```text
System Core
→ GPIO
```

Для PC13 установите:

```text
GPIO output level → High
```

Это сделано потому, что встроенный светодиод на используемой Blue Pill работает по принципу **active-low**.

Это означает:

```text
логический 0 → светодиод включён
логическая 1 → светодиод выключен
```

Поэтому при начальном уровне `High` светодиод после запуска микроконтроллера находится в выключенном состоянии.

> На разных вариантах и клонах Blue Pill аппаратная реализация может отличаться. Перед использованием другой платы следует проверить её схему и маркировку.

---

## 10. Почему светодиод active-low

В используемой плате светодиод включается при низком логическом уровне на PC13.

Поэтому команда:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
```

устанавливает логический `0` и включает светодиод.

А команда:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

устанавливает логическую `1` и выключает светодиод.

Это важно понимать, потому что для других схем подключения светодиода логика может быть противоположной.

---

## 16. Что такое HAL

HAL расшифровывается как:

```text
Hardware Abstraction Layer
```

То есть:

```text
уровень аппаратной абстракции
```

Библиотека HAL позволяет управлять периферией STM32 через готовые функции.

Например:

```c
HAL_GPIO_WritePin();
```

используется для изменения состояния цифрового выхода.

А:

```c
HAL_Delay();
```

используется для создания временной задержки.

На начальном этапе это позволяет сосредоточиться на логике программы и принципах работы периферии, не переходя сразу к непосредственной работе с регистрами микроконтроллера.

## 17. Где писать пользовательский код

STM32CubeMX автоматически генерирует большую часть файла `main.c`.

В нём находятся специальные области:

```c
/* USER CODE BEGIN ... */

/* USER CODE END ... */
```

Пользовательский код рекомендуется писать именно внутри этих областей.

Например:

```c
/* USER CODE BEGIN 3 */

// пользовательский код

/* USER CODE END 3 */
```

### Почему это важно

STM32CubeMX позволяет повторно генерировать проект после изменения конфигурации.

Автоматически созданный код при этом может быть перезаписан.

Код внутри областей `USER CODE` сохраняется.

Поэтому служебные комментарии:

```c
/* USER CODE BEGIN 3 */
/* USER CODE END 3 */
```

удалять или изменять не следует.

## 18. Основной код программы

В бесконечный цикл:

```c
while (1)
```

добавляется следующий код:

```c
/* USER CODE BEGIN 3 */

// Цикл for повторяет код внутри фигурных скобок 5 раз.
// Переменная i используется как счётчик повторений.
// Начальное значение i = 0.
// Условие i < 5 означает: выполнять цикл, пока i меньше 5.
// i++ увеличивает i на единицу после каждого прохода цикла.
for (int i = 0; i < 5; i++)
{
    // HAL_GPIO_WritePin() устанавливает логический уровень
    // на выбранном цифровом выводе GPIO.

    // LED_GPIO_Port — порт, к которому относится светодиод.
    // В данном проекте это GPIOC.

    // LED_Pin — вывод, которому в STM32CubeMX
    // была присвоена пользовательская метка LED.
    // В данном проекте это PC13.

    // GPIO_PIN_RESET устанавливает на выводе логический 0.
    // На используемой Blue Pill встроенный светодиод active-low,
    // поэтому логический 0 ВКЛЮЧАЕТ светодиод.
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);

    // HAL_Delay() останавливает дальнейшее выполнение программы
    // на указанное количество миллисекунд.
    // Здесь светодиод остаётся включённым 300 мс.
    HAL_Delay(300);

    // Повторно вызывается HAL_GPIO_WritePin().
    // GPIO_PIN_SET устанавливает на выводе логическую 1.
    // При active-low подключении это ВЫКЛЮЧАЕТ светодиод.
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);

    // Программа ждёт ещё 300 мс.
    // В течение этого времени светодиод остаётся выключенным.
    HAL_Delay(300);
}

// После выполнения пяти миганий программа делает
// дополнительную паузу длительностью 2000 мс.
// 2000 мс = 2 секунды.
HAL_Delay(2000);

// После выполнения этой строки управление возвращается
// в начало внешнего цикла while(1),
// поэтому вся последовательность повторяется бесконечно.

/* USER CODE END 3 */
```

## 19. Как работает цикл `for`

Используется конструкция:

```c
for (int i = 0; i < 5; i++)
```

Она состоит из трёх частей.

### `int i = 0`

Создаётся переменная-счётчик `i`.

Начальное значение:

```text
0
```

### `i < 5`

Цикл выполняется, пока значение `i` меньше `5`.

### `i++`

После каждого выполнения тела цикла значение `i` увеличивается на единицу.

Таким образом выполняются пять проходов:

```text
i = 0
i = 1
i = 2
i = 3
i = 4
```

После этого условие:

```text
i < 5
```

становится ложным, и программа выходит из цикла.

---

## 20. Как работает `HAL_GPIO_WritePin()`

Функция:

```c
HAL_GPIO_WritePin()
```

управляет состоянием цифрового выхода GPIO.

Вызов:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
```

содержит три аргумента.

### `LED_GPIO_Port`

Порт микроконтроллера.

В данном проекте:

```text
GPIOC
```

### `LED_Pin`

Конкретный вывод порта.

В данном проекте:

```text
PC13
```

### `GPIO_PIN_RESET`

Устанавливает логический уровень `0`.

Для используемого встроенного светодиода это означает:

```text
LED ON
```

---

## 21. Как работает `HAL_Delay()`

Функция:

```c
HAL_Delay();
```

создаёт задержку в миллисекундах.

Например:

```c
HAL_Delay(300);
```

создаёт задержку:

```text
300 мс = 0,3 с
```

Команда:

```c
HAL_Delay(2000);
```

создаёт задержку:

```text
2000 мс = 2 с
```

Для первого учебного проекта такой способ организации времени достаточно прост и понятен.

В более сложных программах длительные блокирующие задержки обычно заменяются таймерами, прерываниями или неблокирующей логикой.

---

## 22. Почему программа выполняется бесконечно

В `main.c` находится конструкция:

```c
while (1)
```

Условие `1` всегда является истинным.

Поэтому код внутри фигурных скобок выполняется бесконечно.

После завершения пяти миганий и двухсекундной паузы программа возвращается к началу `while (1)` и снова выполняет тот же алгоритм.

2. открыть `BluePill_Blink.ioc` в STM32CubeMX;
3. убедиться, что установлен `STM32CubeF1 v1.8.0`;
4. проверить настройки PC13 и SWD;
5. выполнить `GENERATE CODE`;
6. открыть проект в STM32CubeIDE;
7. собрать проект;
8. подключить ST-LINK;
9. выполнить Run.

Такой способ позволяет воспроизвести проект даже при отсутствии служебных файлов конкретного Eclipse Workspace.

## 35. Если STM32CubeMX пытается скачать новую версию F1

Если при генерации проекта появляется запрос на скачивание более новой версии STM32CubeF1, необходимо:

1. открыть `Project Manager`;
2. снять флажок `Use latest available version`;
3. выбрать:

```text
STM32Cube FW_F1 V1.8.0
```

После этого проект может быть сгенерирован с использованием локально установленного firmware package.

## 36. Если STM32CubeMX сообщает об отсутствии сети

При работе offline могут появляться сообщения о невозможности соединения с сервером или Proxy Error.

Если локальный пакет STM32CubeF1 уже установлен, подключение к сети для данного проекта не требуется.

Необходимо отменить сетевую операцию и продолжить работу с локальными компонентами.

## 37. Если программа собирается, но LED не мигает

Проверьте:

- выбран ли STM32F103C8T6;
- настроен ли PC13 как `GPIO_Output`;
- задана ли метка `LED`;
- установлен ли начальный уровень `High`;
- находится ли код внутри `while (1)`;
- используется ли `GPIO_PIN_RESET` для включения LED;
- прошла ли прошивка успешно;
- есть ли сообщение `Download verified successfully`;
- установлена ли перемычка BOOT0 в `0`.

---

## 38. Если ST-LINK не определяется

Проверьте:

- USB-подключение ST-LINK;
- наличие драйвера ST-LINK;
- GND;
- SWDIO;
- SWCLK;
- питание 3.3 V;
- правильность маркировки контактов программатора;
- включение `Serial Wire` в STM32CubeMX.
