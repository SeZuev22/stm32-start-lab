# 7. Что такое GPIO

GPIO расшифровывается как:

```text
General Purpose Input/Output
```

То есть:

```text
цифровой вход/выход общего назначения
```

Вывод микроконтроллера может быть настроен, например:

- как цифровой вход;
- как цифровой выход;
- как альтернативная функция периферии;
- как аналоговый вход.

В данной лабораторной работе вывод:

```text
PC13
```

используется как:

```text
GPIO Output
```

то есть как цифровой выход.

---

# 8. Почему используется PC13

На используемой Blue Pill встроенный пользовательский светодиод подключён к выводу:

```text
PC13
```

Поэтому для первой программы дополнительный внешний светодиод не требуется.

Это позволяет быстро получить первый физический результат работы программы.

---

# 9. Что означает active-low

На используемой Blue Pill встроенный светодиод работает по принципу:

```text
active-low
```

Это означает:

```text
логический 0 → светодиод включён
логическая 1 → светодиод выключен
```

Поэтому:

```c
GPIO_PIN_RESET
```

включает светодиод.

А:

```c
GPIO_PIN_SET
```

выключает его.

Это может показаться непривычным, но является следствием электрической схемы подключения LED на плате.

# 26. USER CODE sections

STM32CubeMX автоматически генерирует значительную часть `main.c`.

В файле находятся специальные области:

```c
/* USER CODE BEGIN ... */

/* USER CODE END ... */
```

Пользовательский код необходимо размещать внутри этих областей.

Например:

```c
/* USER CODE BEGIN 3 */

// пользовательский код

/* USER CODE END 3 */
```

---

## Почему это важно

После изменения конфигурации в STM32CubeMX проект можно сгенерировать повторно.

При этом автоматически созданный код может изменяться.

Код внутри:

```text
USER CODE
```

сохраняется.

Поэтому эти области нельзя удалять без необходимости.

# 28. Код программы Blink

Добавьте:

```c
// Цикл for повторяет код внутри фигурных скобок 5 раз.
// Переменная i используется как счётчик повторений.
// Начальное значение i = 0.
// Условие i < 5 означает: выполнять цикл, пока i меньше 5.
// i++ увеличивает i на единицу после каждого прохода цикла.
for (int i = 0; i < 5; i++)
{
    // Устанавливаем на PC13 логический 0.
    // Встроенный LED Blue Pill работает как active-low,
    // поэтому логический 0 включает светодиод.
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);

    // Светодиод остаётся включённым 300 мс.
    HAL_Delay(300);

    // Устанавливаем на PC13 логическую 1.
    // Для active-low LED это выключает светодиод.
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);

    // Светодиод остаётся выключенным 300 мс.
    HAL_Delay(300);
}

// После пяти миганий выполняется пауза 2 секунды.
HAL_Delay(2000);
```

Продолжение:

![Код Blink — часть 2](../00-getting-started/images/34_blink_code_part2.png)

# 29. Как работает цикл `for`

Строка:

```c
for (int i = 0; i < 5; i++)
```

содержит три части.

## Начальное значение

```c
int i = 0
```

Создаётся переменная `i`.

Начальное значение:

```text
0
```

## Условие

```c
i < 5
```

Цикл выполняется, пока `i` меньше 5.

## Изменение счётчика

```c
i++
```

После каждого прохода:

```text
i = i + 1
```

Получаем:

```text
i = 0
i = 1
i = 2
i = 3
i = 4
```

Итого:

```text
5 повторений
```

# 30. Как работает `HAL_GPIO_WritePin()`

Функция:

```c
HAL_GPIO_WritePin()
```

изменяет логическое состояние выбранного GPIO.

Общий принцип:

```c
HAL_GPIO_WritePin(PORT, PIN, STATE);
```

В нашем проекте:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
```

означает:

```text
PC13 = логический 0
→ LED ON
```

А:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

означает:

```text
PC13 = логическая 1
→ LED OFF
```

---

# 31. Как работает `HAL_Delay()`

Функция:

```c
HAL_Delay(300);
```

создаёт задержку:

```text
300 миллисекунд
```

То есть:

```text
0,3 секунды
```

А:

```c
HAL_Delay(2000);
```

создаёт:

```text
2 секунды
```

# 32. Почему используется `while (1)`

Главная программа STM32 работает внутри бесконечного цикла:

```c
while (1)
```

Условие:

```text
1
```

всегда истинно.

Поэтому после выполнения:

```text
5 миганий
→ пауза
```

программа снова возвращается в начало `while (1)`.

И последовательность повторяется бесконечно.

# 37. Правила подключения

Перед подключением:

1. отключите ST-LINK от USB;
2. проверьте маркировку контактов;
3. соедините GND;
4. соедините 3.3V;
5. соедините SWDIO;
6. соедините SWCLK;
7. ещё раз проверьте соединение;
8. только после этого подключите ST-LINK к USB.

У разных клонов ST-LINK расположение контактов может отличаться.

Ориентируйтесь по:

```text
GND
3.3V
SWDIO
SWCLK
```

а не только по физическому расположению контактов.

Не подключайте:

```text
5V
```

к:


# 45. Типичные ошибки

## Ошибка 1. CubeMX пытается скачать другую версию STM32CubeF1

Проверьте:

```text
Use latest available version
```

Флажок должен быть снят.

Выберите:

```text
STM32Cube FW_F1 V1.8.0
```

---

## Ошибка 2. ST-LINK не определяется

Проверьте:

- USB;
- драйвер ST-LINK;
- GND;
- питание;
- SWDIO;
- SWCLK;
- настройку `Serial Wire`.

---

## Ошибка 3. Проект не собирается

Проверьте Console.

Исправьте все ошибки до перехода к прошивке.

---

## Ошибка 4. Прошивка успешна, но LED не работает

Проверьте:

- PC13;
- `GPIO_Output`;
- User Label `LED`;
- active-low;
- код;
- BOOT0;
- факт запуска программы после прошивки.

---

## Ошибка 5. LED работает наоборот

Помните:

```text
GPIO_PIN_RESET → LED ON
GPIO_PIN_SET   → LED OFF
```

для используемой Blue Pill.
