# Лабораторная работа №1 — дискретный выход STM32 и диагностическая световая сигнализация

[← Подготовка рабочего места](../00-getting-started/README.md) | [↑ Карта курса](../README.md) | [Главная](../../README.md)

## 1. Практическая постановка

Встроенный светодиод Blue Pill используется в этой работе как **модель дискретного диагностического индикатора**.

В реальной технике световая индикация помогает определить состояние устройства без подключения инженерного ПО. Индикатор может условно показывать:

```text
READY
RUN
WARNING
FAULT
NO COMMUNICATION
INITIALIZATION
SERVICE
```

Цель работы — понять, как программное состояние превращается в физический дискретный сигнал:

```text
состояние устройства
↓
алгоритм
↓
HAL
↓
GPIO
↓
физический выход
↓
диагностическая индикация
```

> Используемые в работе световые паттерны учебные. Они не являются универсальным промышленным стандартом сигнализации.

### Где это встречается

Тот же принцип используется в контроллерах, приводах, преобразователях частоты, модулях ввода-вывода, датчиках, сетевых устройствах и локальных диагностических панелях.

В ЛР №1 нагрузкой является только встроенный LED Blue Pill.

> GPIO STM32 — низковольтный логический выход. Он не является готовым промышленным дискретным выходом 24 В и не предназначен для прямого подключения силовой или сетевой нагрузки.

## 2. Цель и ожидаемые результаты

После выполнения работы студент должен уметь:

- создать проект STM32F103C8T6;
- настроить SWD;
- настроить PC13 как GPIO Output;
- объяснить ключевые строки `MX_GPIO_Init()`;
- применять `HAL_GPIO_WritePin()` и `HAL_GPIO_TogglePin()`;
- понимать active-low;
- выполнить Build и прошивку через ST-LINK;
- проверить программу на реальной плате;
- самостоятельно спроектировать простой диагностический паттерн;
- объяснить практический смысл решения.

### Уровни освоения

**Базовый уровень:** корректно выполнить настройку, базовые эксперименты и индивидуальный сценарий, объяснить HAL-функции и алгоритм.

**Углублённый уровень:** дополнительно объяснить сгенерированную инициализацию, найти реализацию HAL-функций в драйвере, связать `WritePin()`/`TogglePin()` с регистрами GPIO и объяснить ограничения `HAL_Delay()`.

## 5. Теоретический минимум

### 5.1. GPIO и PC13

GPIO — `General Purpose Input/Output`, цифровой вход/выход общего назначения.

В этой работе используется:

```text
PC13 → Port C, Pin 13 → GPIO_Output
```

В STM32CubeMX выводу задаётся пользовательская метка `LED`, поэтому в сгенерированном коде используются:

```c
LED_GPIO_Port
LED_Pin
```

Важно различать:

```text
STM32F103C8T6 — микроконтроллер
Blue Pill      — плата на основе микроконтроллера
```

Связь PC13 со встроенным LED — особенность конкретной платы Blue Pill.

### 5.2. Active-low

На проверенной плате LED работает по принципу active-low:

```text
PC13 = 0 → LED ON
PC13 = 1 → LED OFF
```

Следовательно:

```c
GPIO_PIN_RESET  // LED ON
GPIO_PIN_SET    // LED OFF
```

У разных клонов платы аппаратная реализация может отличаться, поэтому фактическое поведение проверяется на стенде.

### 5.3. Основные GPIO-функции HAL

| Функция | Назначение | Уровень в ЛР №1 |
|---|---|---|
| `HAL_GPIO_Init()` | применить конфигурацию GPIO | подробно |
| `HAL_GPIO_DeInit()` | снять пользовательскую конфигурацию | обзор |
| `HAL_GPIO_ReadPin()` | прочитать логический уровень | обзор |
| `HAL_GPIO_WritePin()` | явно установить состояние | обязательно |
| `HAL_GPIO_TogglePin()` | инвертировать текущее состояние | обязательно |
| `HAL_GPIO_LockPin()` | заблокировать конфигурацию до Reset | обзор |
| EXTI-функции | обработка внешних прерываний | последующие темы |

### 5.4. WritePin и TogglePin

`HAL_GPIO_WritePin()` задаёт **конкретное** состояние:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

`HAL_GPIO_TogglePin()` меняет текущее состояние на противоположное:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
```

Главное различие:

```text
WritePin  → установить заданное состояние
TogglePin → изменить текущее состояние
```

### 5.5. HAL_Delay

```c
HAL_Delay(300);
```

создаёт блокирующую задержку приблизительно на 300 мс.

Для первого знакомства с GPIO это удобно, но решение имеет ограничение: во время задержки текущий поток программы не выполняет следующую прикладную логику. Это станет важным при переходе к таймерам и неблокирующим алгоритмам.

### 7.1. `MX_GPIO_Init()`

Для проверенного проекта STM32CubeMX создаёт:

```c
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  __HAL_RCC_GPIOC_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();

  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);

  GPIO_InitStruct.Pin = LED_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);
}
```

Разбор:

- `GPIO_InitTypeDef GPIO_InitStruct = {0};` — структура параметров GPIO;
- `__HAL_RCC_GPIOC_CLK_ENABLE();` — включение тактирования GPIOC;
- `__HAL_RCC_GPIOA_CLK_ENABLE();` — строка присутствует в сгенерированной конфигурации; в ЛР №1 её не изменяем;
- `HAL_GPIO_WritePin(..., GPIO_PIN_SET);` — предварительно задаёт известный уровень;
- поля `Pin`, `Mode`, `Pull`, `Speed` — параметры вывода;
- `HAL_GPIO_Init()` — применяет конфигурацию.

### 7.2. USER CODE sections

Пользовательский код размещается внутри областей:


## 8. Часть А — базовая проверка GPIO

### 8.1. Эксперимент А1: явное управление через WritePin

Внутри `while (1)` выполните:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_Delay(1000);

HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_Delay(1000);
```

Ожидаемый результат:

```text
LED ON  ≈ 1 с
LED OFF ≈ 1 с
повтор
```

Здесь проверяется прямая связь:

```text
HAL → PC13 → LED
```

### 8.2. Эксперимент А2: переключение через TogglePin

Замените пользовательский алгоритм:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(1000);
```

Поскольку `while (1)` повторяется, LED меняет состояние каждую секунду.

Необходимо уметь объяснить, почему одного вызова `TogglePin()` в каждой итерации достаточно для периодического переключения.

## 9. Часть Б — прикладной пример READY

Представим локальное электронное устройство, которое завершило запуск и работает исправно. Требуется дать оператору спокойную визуальную индикацию состояния `READY`.

Выберем учебный паттерн:

```text
короткая вспышка
↓
длинная пауза
↓
повтор
```

Например:

```text
LED ON  — 150 мс
LED OFF — 1850 мс
```

### 9.1. Реализация через WritePin

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_Delay(150);

HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_Delay(1850);
```

### 9.2. Реализация через TogglePin

Перед последовательностью задайте известное состояние:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

Затем:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(150);

HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(1850);
```

Инженерный смысл:

```text
WritePin  → гарантирует исходное состояние
TogglePin → выполняет относительное переключение
```

### 9.3. Контрольная точка Б

- [ ] паттерн READY повторяется стабильно;
- [ ] короткая вспышка визуально отличается от паузы;
- [ ] студент объясняет назначение паттерна;
- [ ] студент понимает, что паттерн является учебным;
- [ ] студент объясняет совместное применение `WritePin()` и `TogglePin()`.

## 10. Часть В — самостоятельная инженерная задача

Студент получает **сценарий**, а не готовый код.

Последовательность работы:

```text
понять состояние устройства
↓
спроектировать паттерн индикации
↓
описать алгоритм словами
↓
реализовать через HAL
↓
прошить и проверить
↓
объяснить решение
```

### 10.1. Ограничения

В индивидуальной части разрешено использовать только материал текущей работы:

- `HAL_GPIO_WritePin()`;
- `HAL_GPIO_TogglePin()`;
- `HAL_Delay()`;
- `for`, если требуется повторяющаяся серия;
- код до `while (1)` и внутри `while (1)`.

Не требуется использовать таймеры, EXTI, RTOS или дополнительную периферию.

### 10.2. Мини-спецификация

До написания кода студент заполняет:

```text

...

Что должен понять оператор:
...

Паттерн индикации:
...

Почему он визуально различим:
...

Как задаётся исходное состояние:
...

...
```

### 10.3. Варианты

| № | Сценарий | Требование к индикации | Что требуется решить самостоятельно |
|---:|---|---|---|
| 1 | HEARTBEAT — контроллер исправен | одна короткая вспышка, длинная пауза | выбрать времена и объяснить «спокойный» характер сигнала |
| 2 | RUN — оборудование работает | равномерное медленное мигание | сделать паттерн отличимым от READY |
| 3 | WARNING — предупреждение | две короткие вспышки, затем пауза | применить `for`, выбрать длительности |
| 4 | FAULT — аварийное состояние | серия не менее четырёх быстрых вспышек, затем пауза | сделать сигнал визуально заметнее READY/RUN |
| 5 | COMMUNICATION LOST — потеря связи | три короткие + одна длинная вспышка + пауза | подобрать отчётливо различимые длительности |
| 6 | INITIALIZATION → READY | пять быстрых вспышек один раз после запуска, затем постоянный READY | правильно разделить одноразовый код и `while (1)` |
| 7 | SERVICE MODE — обслуживание | две длинные вспышки, затем пауза | отличить от WARNING с двумя короткими |
| 8 | SENSOR WAIT — ожидание датчика | короткая → длинная → короткая → пауза | правильно организовать последовательность |
| 9 | REMOTE MODE — дистанционный режим | короткая → короткая → длинная → пауза | выбрать времена и обосновать распознаваемость |
| 10 | Собственная диагностика | придумать два состояния и два различимых паттерна | реализовать один паттерн по указанию преподавателя и объяснить второй |

> FAULT/WARNING и другие названия в таблице используются как учебные сценарии. Они не задают нормативную промышленную цветовую или временную сигнализацию.

### 10.4. Что считается самостоятельным решением

Недостаточно заменить одно число в готовом примере.

Студент самостоятельно определяет:

- последовательность состояний ON/OFF;
- количество повторов;
- место межсерийной паузы;

- где нужен `WritePin()`;

- как обеспечить предсказуемое исходное состояние.

## 11. Углублённый разбор HAL

Исходный код используемого GPIO-драйвера находится непосредственно в проекте:

- **[`stm32f1xx_hal_gpio.h`](project/Drivers/STM32F1xx_HAL_Driver/Inc/stm32f1xx_hal_gpio.h)**;
- **[`stm32f1xx_hal_gpio.c`](project/Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_gpio.c)**.

Для углублённого уровня рекомендуется найти реализации:

```c
HAL_GPIO_Init()
HAL_GPIO_WritePin()
HAL_GPIO_TogglePin()
HAL_GPIO_ReadPin()
```

В STM32F1 изменение состояния GPIO связано, в частности, с регистрами `BSRR` и `ODR`. Подробное изучение регистров не является обязательным для базового прохождения ЛР №1, но позволяет понять, что происходит под уровнем HAL.

## 12. Инженерная интерпретация и ограничение решения

В этой работе реализована цепочка:

```text
состояние программы
↓
GPIO-команда
↓
низковольтный физический выход
↓
индикатор
```

Концептуально это похоже на управление дискретным сигналом в системе автоматики, но электрический интерфейс промышленного оборудования выполняется отдельными аппаратными средствами.

Текущее временное управление основано на `HAL_Delay()`. Для одного LED это удобно. Если программа одновременно должна читать входы, обслуживать связь и формировать несколько процессов, блокирующие задержки становятся ограничением. Это подводит к следующим темам курса.

## 13. Типовые ошибки

### LED работает «наоборот»

На проверенной Blue Pill:

```text
RESET → ON
SET   → OFF
```

Причина — active-low.

### Toggle начинается не с ожидаемого состояния

`TogglePin()` зависит от текущего уровня. Перед диагностической последовательностью задайте известное состояние через `WritePin()`.

### Паттерн трудно распознать

Проверьте:

- достаточно ли различаются короткая и длинная вспышки;
- есть ли заметная пауза между сериями;
- правильно ли организован цикл;
- не перепутано ли состояние active-low.

Сначала исправьте словесный алгоритм, затем код.

### ST-LINK не программирует плату

Проверьте последовательно:

```text
USB
→ GND
→ 3.3V
→ SWDIO
→ SWCLK
→ Serial Wire
→ BOOT0 = 0
```

## 15. Требования к отчёту

Отчёт должен содержать:

1. название и цель работы;
2. оборудование и программное обеспечение;
3. краткую практическую постановку;
4. конфигурацию STM32CubeMX;
5. объяснение active-low и ключевых строк `MX_GPIO_Init()`;
6. результат части А;
7. результат прикладного примера READY;
8. номер индивидуального варианта;
9. заполненную мини-спецификацию;
10. алгоритм словами или временной схемой;
11. пользовательский код;
12. фактический результат на плате;
13. объяснение практического смысла решения;
14. вывод.

Отдельный арифметический расчёт периода в ЛР №1 не требуется.

## 16. Требования к защите

Студент должен:

- объяснить конфигурацию PC13 и active-low;
- объяснить ключевые строки `MX_GPIO_Init()`;
- показать различие `WritePin()` и `TogglePin()`;
- объяснить назначение своего диагностического паттерна;
- показать работающий вариант;
- по просьбе преподавателя изменить один параметр алгоритма и заранее объяснить ожидаемый эффект;
- назвать пример реального применения диагностической индикации.

Для углублённого уровня дополнительно требуется показать в исходнике HAL реализацию одной из используемых GPIO-функций и объяснить ограничение блокирующего `HAL_Delay()`.

Работающая прошивка без понимания алгоритма не является достаточным результатом защиты.

## 18. Что дальше

После GPIO Output логично перейти к получению внешнего дискретного сигнала и реакции на событие. Возможные направления: GPIO Input, `HAL_GPIO_ReadPin()`, EXTI, таймеры и неблокирующие алгоритмы. Конкретное содержание ЛР №2 определяется после согласования с преподавателем.
