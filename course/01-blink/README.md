# Создание первого проекта STM32 и управление цифровым выходом GPIO

Лабораторная работа выполняется **полностью** и состоит из трёх обязательных частей:

```text
А — повторить проверенный базовый проект
↓
Б — исследовать HAL_GPIO_TogglePin()
↓
В — выполнить индивидуальный вариант
```

Работа считается завершённой только после выполнения всех трёх частей, проверки результата на реальной плате и ответов на контрольные вопросы.

---

# 1. Цель работы

Освоить полный базовый цикл разработки программы для микроконтроллера STM32F103C8T6 и научиться управлять цифровым выходом GPIO на примере встроенного светодиода Blue Pill.

В ходе работы требуется:

- создать проект STM32CubeMX;
- выбрать STM32F103C8T6;
- включить SWD;
- настроить PC13 как GPIO Output;
- сгенерировать проект для STM32CubeIDE;
- разобраться в структуре проекта;
- использовать `HAL_GPIO_WritePin()` и `HAL_GPIO_TogglePin()`;
- использовать `HAL_Delay()` и цикл `for`;
- выполнить Build;
- прошить STM32 через ST-LINK V2;
- проверить базовый алгоритм;
- выполнить индивидуальный вариант;
- рассчитать длительность одного полного цикла индивидуальной программы;
- объяснить связь между кодом и поведением реального устройства.

# 7. Краткая теория

## 7.1. GPIO

GPIO — `General Purpose Input/Output`, цифровой вход/выход общего назначения.

В данной работе:

```text
PC13 → GPIO_Output
```

Микроконтроллер формирует на этом выводе логический уровень 0 или 1.

## 7.2. PC13

```text
PC13 = Port C, Pin 13
```

На проверенной Blue Pill встроенный пользовательский светодиод связан с PC13.

Важно различать:

```text
PC13 — вывод микроконтроллера
LED  — элемент платы Blue Pill
```

## 7.3. Active-low

На проверенной плате светодиод активен низким уровнем:

```text
0 → LED ON
1 → LED OFF
```

Поэтому:

```c
GPIO_PIN_RESET
```

включает LED, а:

```c
GPIO_PIN_SET
```

выключает LED.

## 7.4. SWD

SWD — `Serial Wire Debug`.

В работе используются:

```text
PA13 → SWDIO
PA14 → SWCLK
```

через которые ST-LINK программирует и отлаживает STM32.

# 18. Разбор базовой программы

## Цикл `for`

```c
for (int i = 0; i < 5; i++)
```

означает пять повторений тела цикла.

```text
i = 0, 1, 2, 3, 4
```

## Включение LED

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
```

формирует логический 0 на PC13, поэтому active-low LED включается.

## Задержка

```c
HAL_Delay(300);
```

останавливает дальнейшее выполнение на 300 мс.

## Выключение LED

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

формирует логическую 1, поэтому LED выключается.

## Пауза серии

```c
HAL_Delay(2000);
```

создаёт паузу 2 с после пяти миганий.

## Почему всё повторяется

Код находится внутри:

```c
while (1)
```

поэтому после паузы выполнение возвращается в начало бесконечного цикла.

# Часть Б. Обязательное исследование `HAL_GPIO_TogglePin()`

# 23. Что делает `HAL_GPIO_TogglePin()`

Функция:

```c
HAL_GPIO_TogglePin(GPIOx, GPIO_Pin);
```

инвертирует текущее состояние выбранного GPIO:

```text
0 → 1
1 → 0
```

Для нашего проекта:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
```

Если PC13 был `High`, после вызова станет `Low`.

Если PC13 был `Low`, после следующего вызова станет `High`.

Так как LED active-low:

| До вызова | После вызова | LED после вызова |
|---|---|---|
| High | Low | ON |
| Low | High | OFF |

---

# 24. Обязательный эксперимент TogglePin

Временно замените содержимое `USER CODE BEGIN 3` / `USER CODE END 3` на:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(1000);
```

Выполните:

```text
Build
→ Run
```

Требуемый результат:

```text
состояние LED меняется каждые 1000 мс
```

Обратите внимание: один вызов `TogglePin()` не означает «одно мигание». Он означает только **одно изменение состояния**.

Полное мигание от состояния OFF обратно к OFF требует двух переключений:

```text
OFF
→ TogglePin
ON
→ Delay
→ TogglePin
OFF
→ Delay
```

# 25. Контрольная точка Б

Требуется уметь объяснить:

1. чем `HAL_GPIO_TogglePin()` отличается от `HAL_GPIO_WritePin()`;
2. почему результат `TogglePin()` зависит от предыдущего состояния GPIO;
3. почему для одного полного мигания требуется два переключения;
4. почему начальный уровень `High` удобен для active-low LED;
5. что произойдёт после нечётного количества вызовов `TogglePin()` без второго переключения.

После проверки верните программу к рабочему состоянию и переходите к индивидуальному варианту.

# Часть В. Индивидуальное задание

# 26. Требования к индивидуальному варианту

Индивидуальная программа должна состоять из:

```text
Серия A
↓
Пауза между сериями
↓
Серия B
↓
Пауза между полными циклами
↓
повтор
```

Для каждой серии задаются:

```text
N      — количество миганий
tON    — длительность включения LED
tOFF   — длительность выключения LED
```

В индивидуальной части обязательно:

- использовать `HAL_GPIO_TogglePin()` для управления LED;
- использовать отдельный цикл `for` для серии A;
- использовать отдельный цикл `for` для серии B;
- использовать `HAL_Delay()`;
- обеспечить выключенное состояние LED во время пауз;
- не использовать таймеры, прерывания или другую периферию;
- рассчитать длительность полного цикла программы;
- проверить полученный алгоритм на реальной плате.

В индивидуальной части **не используйте `HAL_GPIO_WritePin()` для формирования самих миганий**.

---

# 27. Алгоритм одной серии через TogglePin

Для одной серии логика должна быть следующей:

```text
начало серии
↓
TogglePin → LED ON
↓
tON
↓
TogglePin → LED OFF
↓
tOFF
↓
повторить N раз
```

То есть внутри одного повторения цикла `for` требуется два вызова `HAL_GPIO_TogglePin()`.

Готовый код индивидуального варианта в методичке не приводится. Все необходимые элементы для его самостоятельного составления уже разобраны выше.

---

# 28. Расчёт длительности цикла

Для серии A:

```text
TA = NA × (tA_ON + tA_OFF)
```

Для серии B:

```text
TB = NB × (tB_ON + tB_OFF)
```

Полная длительность одного цикла:

```text
Tcycle = TA + PAB + TB + PCYCLE
```

где:

```text
PAB     — пауза между сериями A и B
PCYCLE  — пауза между полными циклами
```

Все величины удобно рассчитывать в миллисекундах.

## Пример расчёта, не являющийся вариантом

Пусть:

```text
NA = 2
tA_ON = 200 мс
tA_OFF = 300 мс
PAB = 500 мс
NB = 1
tB_ON = 700 мс
tB_OFF = 300 мс
PCYCLE = 1500 мс
```

Тогда:

```text
TA = 2 × (200 + 300) = 1000 мс
TB = 1 × (700 + 300) = 1000 мс
Tcycle = 1000 + 500 + 1000 + 1500 = 4000 мс
```

Следовательно, один полный цикл длится:

```text
4 с
```

- [ ] Build выполняется без ошибок;
- [ ] прошивка выполняется успешно;
- [ ] фактический алгоритм соответствует заданию;
- [ ] студент может объяснить каждое изменение программы.

# 32. Типичные ошибки индивидуальной части

## LED после серии остаётся включённым

Причина часто заключается в нечётном количестве переключений состояния.

Для одного полного мигания требуется:

```text
Toggle → ON
Toggle → OFF
```

## Первая серия работает, вторая начинается неправильным состоянием

Проверьте, что каждая серия заканчивается состоянием OFF и что внутри каждого повторения выполнены два переключения.

## Пауза визуально выглядит как включённый LED

Во время паузы LED должен быть выключен. Проверьте состояние выхода непосредственно перед `HAL_Delay()` паузы.

## Времена не соответствуют варианту

Сверьте каждое значение с таблицей и отдельно проверьте `tON`, `tOFF`, `PAB`, `PCYCLE`.
