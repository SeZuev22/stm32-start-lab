# 1. Практическая задача

В этой работе встроенный светодиод Blue Pill используется как **модель дискретного индикатора состояния устройства**.

В реальной технике световая индикация помогает быстро понять состояние оборудования без подключения компьютера или диагностического ПО.

Например, индикатор может условно сообщать:

```text
READY
RUN
WARNING
FAULT
NO COMMUNICATION
INITIALIZATION
SERVICE
```

В ЛР №1 студент учится формировать такие дискретные сигналы средствами GPIO и HAL.

> Световые коды, приведённые в работе, являются учебными и не являются универсальным промышленным стандартом.

---

# 2. Где это встречается на практике

Тот же общий принцип используется в:

- контроллерах;
- преобразователях частоты;
- приводах;
- модулях ввода-вывода;
- сетевых устройствах;
- датчиках;
- встраиваемых системах;
- локальных панелях диагностики.

Устройство имеет внутреннее состояние:

```text
READY / RUN / WARNING / FAULT
```

а программа преобразует его в понятный человеку сигнал.

В этой работе нагрузкой является только встроенный LED Blue Pill.

> GPIO STM32 работает с низковольтными логическими уровнями и не является промышленным дискретным выходом 24 В. Прямое подключение промышленной лампы, реле или иной силовой нагрузки к GPIO в этой работе не рассматривается.

# 3. Цель работы

Изучить настройку цифрового выхода GPIO STM32F103C8T6 и научиться использовать HAL для реализации простой диагностической сигнализации состояния устройства.

После выполнения работы студент должен уметь:

- создать проект STM32F103C8T6;
- настроить SWD;
- настроить PC13 как GPIO Output;
- объяснить основные строки `MX_GPIO_Init()`;
- использовать `HAL_GPIO_WritePin()`;
- использовать `HAL_GPIO_TogglePin()`;
- понимать назначение других основных функций GPIO HAL;
- понимать active-low;
- прошить программу через ST-LINK;
- проверить результат на реальной плате;
- построить световой алгоритм по заданному сценарию;
- объяснить практический смысл реализованного алгоритма.

# 9. Микроконтроллер и плата — не одно и то же

```text
STM32F103C8T6 — микроконтроллер
Blue Pill      — учебная плата
```

Связь PC13 со встроенным LED является особенностью платы Blue Pill.

# 10. Active-low

На проверенной Blue Pill LED работает как:

```text
PC13 = 0 → LED ON
PC13 = 1 → LED OFF
```

Поэтому:

```c
GPIO_PIN_RESET
```

включает LED, а:

```c
GPIO_PIN_SET
```

выключает LED.

# 14. Параметры GPIO

Используются:

```text
GPIO output level: High
GPIO mode: Output Push Pull
GPIO Pull-up/Pull-down: No pull-up and no pull-down
Maximum output speed: Low
User Label: LED
```

Что это означает:

- `High` — начальное состояние PC13 равно логической 1; для active-low LED это `OFF`;
- `GPIO_MODE_OUTPUT_PP` — выход Push-Pull;
- `GPIO_NOPULL` — внутренняя подтяжка не используется;
- `GPIO_SPEED_FREQ_LOW` — низкая скорость переключения выходного драйвера.

Важно:

> `GPIO_SPEED_FREQ_LOW` не задаёт частоту мигания. Временной алгоритм в этой работе формируется через `HAL_Delay()`.

# 19. `MX_GPIO_Init()`

STM32CubeMX автоматически создаёт функцию:

```c
MX_GPIO_Init();
```

Для проверенного проекта она содержит:

```c
static void MX_GPIO_Init(void)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  __HAL_RCC_GPIOC_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();

  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);

  GPIO_InitStruct.Pin = LED_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;

  HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);
}
```

Студент должен понимать назначение каждой группы строк.

---

# 20. Что делает `GPIO_InitTypeDef`

```c
GPIO_InitTypeDef GPIO_InitStruct = {0};
```

создаёт структуру, в которой задаются:

```text
Pin
Mode
Pull
Speed
```

---

# 21. Тактирование GPIO

```c
__HAL_RCC_GPIOC_CLK_ENABLE();
```

включает тактирование GPIOC.

PC13 относится к порту C, поэтому GPIOC должен быть доступен периферийной системе микроконтроллера.

В проекте также присутствует:

```c
__HAL_RCC_GPIOA_CLK_ENABLE();
```

Автоматически сгенерированную строку удалять не требуется.

# 22. Начальное состояние LED

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

Для active-low означает:

```text
LED OFF
```

То есть программа начинает работу из известного состояния.

# 23. Применение конфигурации

```c
GPIO_InitStruct.Pin = LED_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;

HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);
```

`HAL_GPIO_Init()` применяет параметры к выбранному GPIO.

---

# 24. Что такое HAL

HAL:

```text
Hardware Abstraction Layer
```

позволяет управлять периферией через готовые функции.

Для GPIO важно знать:

| Функция | Назначение | ЛР №1 |
|---|---|---|
| `HAL_GPIO_Init()` | настройка GPIO | подробно |
| `HAL_GPIO_DeInit()` | сброс конфигурации | обзор |
| `HAL_GPIO_ReadPin()` | чтение уровня | обзор |
| `HAL_GPIO_WritePin()` | явная установка 0/1 | обязательно |
| `HAL_GPIO_TogglePin()` | инверсия состояния | обязательно |
| `HAL_GPIO_LockPin()` | блокировка конфигурации | обзор |
| EXTI-функции | внешние прерывания | будущая ЛР |

---

# 25. `HAL_GPIO_WritePin()`

Общий вид:

```c
HAL_GPIO_WritePin(GPIOx, GPIO_Pin, PinState);
```

Для LED:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
```

означает:

```text
LED ON
```

А:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

означает:

```text
LED OFF
```

`WritePin()` удобно использовать, когда необходимо **явно задать известное состояние**.

---

# 26. `HAL_GPIO_TogglePin()`

```c
HAL_GPIO_TogglePin(GPIOx, GPIO_Pin);
```

выполняет:

```text
0 → 1
1 → 0
```

То есть меняет текущее состояние на противоположное.

---

# 27. Главное отличие WritePin и TogglePin

```text
WritePin
→ установить конкретное состояние
```

```text
TogglePin
→ изменить текущее состояние
```

Поэтому при использовании `TogglePin()` необходимо понимать, в каком состоянии выход находится до первого переключения.

---

# 28. `HAL_Delay()`

```c
HAL_Delay(300);
```

создаёт блокирующую задержку примерно на 300 мс.

Для первой работы это допустимо.

Но важно понимать ограничение:

> во время `HAL_Delay()` текущий поток программы ожидает.

Позже это станет причиной перехода к таймерам, прерываниям и неблокирующим алгоритмам.

# Часть А. Проверка цифрового выхода

# 30. Эксперимент А1 — WritePin

Внутри `while (1)`:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_Delay(1000);

HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_Delay(1000);
```

Ожидаемый результат:

```text
LED ON  ≈ 1 с
LED OFF ≈ 1 с
повтор
```

Задача этого шага — увидеть прямую связь:

```text
HAL
↓
PC13
↓
LED
```

---

# 31. Эксперимент А2 — TogglePin

Замените пользовательский алгоритм на:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(1000);
```

Так как `while (1)` повторяется, LED меняет состояние каждую секунду.

Студент должен объяснить, почему одного вызова `TogglePin()` достаточно для периодического переключения.

# Часть Б. Практический пример

# 34. Задача: сигнал READY

Представим локальное электронное устройство.

Оно завершило запуск и работает исправно.

Требуется дать оператору спокойную визуальную индикацию:

```text
READY
```

Для учебного примера выберем:

```text
короткая вспышка
↓
длинная пауза
↓
повтор
```

Например:

```text
LED ON  — 150 мс
LED OFF — 1850 мс
```

Это **учебный световой код**, а не промышленный стандарт.

---

# 35. READY через WritePin

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_Delay(150);

HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_Delay(1850);
```

Код находится внутри:

```c
while (1)
```

и повторяется постоянно.

---

# 36. Что здесь уже является инженерной задачей

Теперь цепочка выглядит так:

```text
состояние устройства
READY
↓
правило индикации
короткая вспышка
↓
алгоритм
ON → delay → OFF → delay
↓
HAL
↓
GPIO
↓
LED
```

LED больше не является целью работы. Он отображает состояние условной системы.

---

# 37. READY через TogglePin

Сначала задайте известное состояние:

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```

Затем:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(150);

HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(1850);
```

Здесь:

```text
WritePin → задаёт известное начальное состояние
TogglePin → выполняет переключения
```

# 40. Общие требования

Во всех вариантах:

1. использовать только материал ЛР №1;
2. применять `HAL_GPIO_WritePin()` и/или `HAL_GPIO_TogglePin()`;
3. применять `HAL_Delay()`;
4. обеспечить известное начальное состояние;
5. не использовать таймеры, прерывания, RTOS и дополнительную периферию;
6. до написания кода описать алгоритм словами;
7. сделать световой код визуально различимым;
8. объяснить практический смысл решения.

Цикл `for` допускается и рекомендуется для повторяющихся серий.

```text
до while (1)
```

и:

```text
внутри while (1)
```

---

# 48. Вариант 7 — SERVICE MODE

Состояние:

```text
режим обслуживания
```

Требуется:

```text
2 длинные вспышки
↓
пауза
↓
повтор
```

Сигнал должен отличаться от WARNING с двумя короткими вспышками.

# 49. Вариант 8 — SENSOR WAIT

Состояние:

```text
ожидание готовности датчика
```

Требуется:

```text
короткая
↓
длинная
↓
короткая
↓
пауза
↓
повтор
```

# 50. Вариант 9 — REMOTE MODE

Состояние:

```text
дистанционный режим
```

Требуется повторяющийся код:

```text
короткая
короткая
длинная
↓
пауза
```

Студент сам выбирает длительности и обосновывает различимость.

---

# 51. Вариант 10 — собственная двухсостоянийная диагностика

Требуется придумать два состояния одного условного устройства.

Например:

```text
READY / FAULT
LOCAL / REMOTE
WAIT / RUN
```

Для каждого состояния:

- придумать различимый световой код;
- записать мини-спецификацию;
- реализовать на плате один код, назначенный преподавателем;
- объяснить, чем два кода отличаются.

---

# 52. Что считается самостоятельным решением

Самостоятельная работа — не замена одного числа.

Студент должен сам определить:

- последовательность ON/OFF;
- количество повторов;
- место длинной паузы;
- где нужен `for`;
- где лучше `WritePin()`;
- где удобнее `TogglePin()`;
- как гарантировать правильное начальное состояние.

---

# 53. Проверка до Build

Перед компиляцией студент должен уметь словами прочитать свой алгоритм:

```text
что происходит с LED
↓
сколько раз
↓
какая пауза
↓
что будет после серии
↓
почему алгоритм повторяется
```

Если программа не может быть объяснена словами, она ещё не готова к проверке.

---

# 55. Почему это связано с автоматизацией

Концептуально:

```text
состояние программы
↓
дискретный сигнал
↓
физический индикатор
```

Это тот же общий подход, который применяется при формировании сигналов состояния в системах управления.

Но электрически:

```text
GPIO STM32
```

не равен:

```text
промышленному дискретному выходу
```

В первой работе изучается **логика**, а не силовой интерфейс.

---

# 56. Ограничение текущего решения

Сейчас временная логика строится на:

```c
HAL_Delay()
```

Для одного LED это удобно.

Но если одновременно нужно:

```text
читать кнопку
обрабатывать датчик
обмениваться по UART
обслуживать несколько сигналов
```

длительные блокирующие задержки становятся неудобными.

Это естественный переход к последующим темам.

---

# 57. Типовые ошибки

## LED работает наоборот

```text
RESET → ON
SET   → OFF
```

Причина: active-low.

## Toggle начинает не с той фазы

Причина:

```text
TogglePin зависит от текущего состояния
```

Задайте состояние через `WritePin()` перед последовательностью.

## Паттерн невозможно распознать

Причины:

- короткая и длинная вспышки слишком похожи;
- нет выраженной паузы между сериями;
- задержки стоят не в том месте;
- цикл организован неверно.

Сначала исправьте словесный алгоритм, затем код.
